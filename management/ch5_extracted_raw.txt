Chapter 5: SYSTEM IMPLEMENTATION AND TESTING 
5.1 Introduction 
This chapter presents the comprehensive technical implementation, operational architecture, 
verification procedures, and empirical evaluation of the system, a dualparadigm  semantic 
micro-learning and mentorship matching platform. The engineered system addresses the 
fragmentation and generalized ambiguity of conventional learning management systems by 
integrating dense mathematical vector retrieval, structured occupational f rameworks from the 
U.S. Bureau of Labor Statistics, automated multi-source instructional ingestion, and real-time 
expert mentorship matching. Rather than utilizing  isolated or localized heuristic rules, the 
platform unifies learner onboarding, progress tracking, daily learning drops, and mentor 
interactions into an end -to-end operational software ecosystem. The structure of this chapter 
systematically details the te chnological runtime environment, database schema, and vector 
store configurations. Subsequent sections articulate the concrete implementation of the four 
primary operational subsystems: Module One for diagnostic onboarding and behavioral 
baseline calibration; Module Two for profile dashboards, competency visualizers, and skill 
graph gap analysis; Module Three for the daily focus drop engine, multiadapter educational 
ingestion, and autonomous diagnostic quiz synthesis; and Module Four for the mentorship 
marketplace, weekly capacity booking algorithms, direct messaging communication, and real-
time notification dispatching. Finally, functional ve rification records and empirical ablation 
experiments validate the robustness and pedagogical relevance of the deployed framework 
5.2 Description of the Implementation Environment 
The implementation environment was architected to balance computational throughput for 
dense vector operations with resource efficiency across decoupled cloud platforms. The 
infrastructure comprises a high-performance local engineering workstation, a cloud -managed 
PostgreSQL database engine with native vector search extensions, and scalable asynchronous 
backend and frontend application servers.

5.3 Data Preparation and Vector Store Architecture 
A foundational challenge in career mentorship systems is bridging the semantic gap between 
informal user queries and standardized industry taxonomies. The data preparation layer 
establishes a standardized knowledge graph that maps occupations, competency r ubrics, and 
micro-content items into a unified 384-dimensional semantic metric space. 
5.3.1 Career Taxonomy and Technical Skill Framework 
The system knowledge base is anchored upon the Standard Occupational Classification (SOC) 
system published by the U.S. Bureau of Labor Statistics and the O*NET 28.0 database. The 
catalog encompasses 855 curated career profiles organized into 23 official SOC Major Groups, 
spanning management (Group 11), computer and mathematical occupations (Group 15), 
healthcare practitioners (Group 29), healthcare support (Group 31), and office administration 
(Group 43). Each career is linked to essential competency pillars, where skills are categorized 
into technical proficiencies, workplace competencies, and diagnostic behavioral anchors. This 
hierarchical structure prevents ad-hoc classification errors by providing an official taxonomic 
foundation for all automated guidance. 
5.3.2 Educational Micro-Content Corpus Preparation 
To ensure high pedagogical retention, learning materials are structured as bite -sized 
microcontent records rather than long-form, unstructured documents. Each micro-content entry 
in the database encapsulates a specific instructional concept, verified workp lace scenarios, 
summary key points, and five diagnostic checkpoint questions. The repository maintains 
verified learning modules sourced from open educational textbooks, official developer 
documentation, peerreviewed clinical databases, and accredited video lecture transcripts 
5.3.3 384-Dimensional Semantic Embedding Pipeline 
Every career title, competency rubric, and educational lesson is embedded into a dense 384 - 
dimensional continuous vector space using the all -MiniLM-L6-v2 sentence transformer 
architecture. By leveraging the FastEmbed ONNX runtime engine, token embeddings are 
computed locally in 8 to 12 milliseconds without incurring external network latency or GPU 
hardware dependencies. The resulting normalized vector representations allow semantic 
similarity to be measured directly via vector cosine dot products, ensuring  that conceptual 
synonyms such as 'front-end engineer' and 'React web developer' project into proximate spatial 
coordinates.

5.3.4 Database Vector Indexing via pgvector and HNSW 
Persistent storage and rapid similarity search are executed within PostgreSQL using the 
pgvector extension. Career and content tables are indexed using Hierarchical Navigable Small 
World (HNSW) graphs configured with cosine distance operator metrics. The HNSW indexing 
parameter m was calibrated to 16 with an ef_construction value of 64, enabling sub -
fivemillisecond approximate nearest neighbor (ANN) retrieval across thousands of vectorized 
database records. Row-level security policies enforce multi-tenant isolation, guaranteeing that 
learners only query authenticated data structures.

5.4.7 Multi-Source Educational Content Ingestion and Validation Pipeline

5.6.2 Inference Runtime Optimization: FastEmbed ONNX vs. PyTorch  
A critical engineering priority was optimizing neural inference latency on CPU hardware. By 
transitioning from a standard PyTorch transformer pipeline to the FastEmbed ONNX runtime 
engine, average vector embedding latency decreased from 142.6 milliseconds to 11.4 
milliseconds per query —a 12.5 -fold performance improvement. Memory footprint was 
concurrently reduced from 850 MB to 125 MB, enabling smooth deployment on 
memoryconstrained cloud environments.  
5.6.3 Content Ingestion Filtering Efficiency  
During live continuous ingestion, third-party instructional candidates were processed through 
the multi-stage quality filter. Out of 1,200 raw web candidates, 28.4 percent were rejected for 
insufficient body length (< 200 characters), 18.2 percent were eliminated by semantic domain 
incongruence, and 8.5 percent were discarded for invalid quiz structures. The surviving 44.9 
percent of candidates achieved an average pedagogical trust score of 0.94.  
5.6.4 Two-Stage Recommendation Re-Ranking Dynamics and Ablation  
Ablation experiments demonstrated the statistical superiority of the two -stage hybrid 
recommendation pipeline over single -stage vector retrieval. Stage One executes coarse sub -
five millisecond vector candidate retrieval. Stage Two applies pedagogical graph re -ranking 
incorporating skill gap severity, prerequisite unblocking potential, and source diversity 
penalties. The hybrid model achieved an NDCG@5 ranking accuracy of 0.924, significantly 
outperforming pure vector similarity (0.761) and popularity-based baselines (0.542).

5.7.3 Environment Isolation and Security Practices

isolated within git -ignored environment variable files (.env). Supabase Row -Level Security 
(RLS) policies enforce least-privilege data access, ensuring that learners can never alter mentor 
availability records and mentors cannot manipulate peer assessments.

on Netlify, and persistent data resides in a managed Supabase PostgreSQL cloud cluster.
